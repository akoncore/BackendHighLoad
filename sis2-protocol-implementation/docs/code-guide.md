# Код простыми словами

## Что делает приложение

Это список товаров. У каждого товара есть id, название, цена, остаток и версия.
Программа умеет добавить, найти, показать список, изменить и удалить товар.

REST и gRPC — два способа обратиться к одной программе.
REST принимает JSON по HTTP. gRPC принимает сообщения, описанные в product.proto.
Оба вызывают один ProductService и видят одинаковые данные.

## Один пример: создание товара

1. Клиент отправляет название, цену, валюту, категорию, остаток и уникальный ключ.
2. Контроллер передаёт данные в ProductService.
3. Сервис проверяет поля и приводит цену к двум знакам после точки.
4. В транзакции резервирует ключ, создаёт товар и сохраняет ответ.
5. После commit возвращает результат клиенту.

Транзакция означает: либо записано всё, либо не записано ничего.

## Зачем нужен Idempotency-Key

Представьте, что сервер создал товар, а ответ потерялся.
Клиент не знает, завершилась ли операция, и отправляет запрос ещё раз.
Без ключа появился бы второй товар. С ключом сервер возвращает сохранённый ответ.

Ключ — UUID, например `51e2d4ab-1234-4ace-88f9-123456789abc`.
Для повторов одной операции используйте тот же ключ.
Для нового товара создавайте новый ключ.

Уникальность ключа проверяет база. Поэтому защита работает и между процессами,
подключёнными к одной PostgreSQL. В тесте проверены параллельные REST/gRPC-запросы
к одному процессу; отдельный многопроцессный тест не проводился.

Если два запроса пришли одновременно, второй ждёт завершения первого в пределах
тайм-аутов БД, затем получает исходный ответ. Другая нагрузка с тем же ключом — 422.

## Зачем нужна version

Два человека прочитали товар с version=1.
Первый обновил товар: теперь version=2.
Второй пытается сохранить старую копию с version=1.
Сервер отклоняет изменение, чтобы не потерять работу первого человека.

В SQL это условие `WHERE id=? AND version=?`.
Проверка версии и запись выполняются атомарно.
Клиенту нужно перечитать товар и осознанно повторить изменение.

## Почему цена — строка

Во внешнем API используется `"750000.00"`.
В Java для расчётов и SQL-записи используется BigDecimal.
В PostgreSQL — DECIMAL(19,2). Тип double не используется для денег.

## Что означают аннотации

| Код | Значение |
|---|---|
| @SpringBootApplication | Точка запуска Spring |
| @RestController | Класс принимает HTTP-запросы |
| @GetMapping, @PostMapping | Какой HTTP-метод вызывает функцию |
| @Service | Здесь находятся правила работы |
| @Repository | Здесь работа с базой |
| @Bean | Spring создаёт и хранит этот объект |

Spring сам передаёт зависимости в конструкторы.
Например, ProductController получает готовый ProductService.

## Почему есть отдельные request и response

ProductInput содержит только разрешённые входные поля.
Product содержит также id, version и updated_at: их назначает сервер.
Клиент не может подменить id при создании через JSON.

## Понятия для защиты

- CRUD — создание, чтение, обновление, удаление.
- Protobuf — формат сообщений gRPC.
- Deadline — момент, после которого клиент больше не ждёт.
- Retry — повтор временно неудачного запроса.
- p99 — 99% успешных запросов завершились не медленнее этого значения.
- RPS — число успешных запросов в секунду.

Тайм-аут не означает, что запись точно отменена: сервер мог успеть её выполнить.
Поэтому после потери ответа на создание нужен прежний Idempotency-Key.
