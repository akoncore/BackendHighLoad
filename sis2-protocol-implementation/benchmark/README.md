# Benchmark

Код: `src/main/java/com/akon/catalog/benchmark/BenchmarkRunner.java`.
Он находится в src/main/java, чтобы Maven компилировал его без дополнительных настроек.

1. Запустите сервис в отдельном терминале.
2. В корне проекта выполните:

```powershell
.\mvnw.cmd compile exec:java "-Dexec.mainClass=com.akon.catalog.benchmark.BenchmarkRunner" "-Dexec.args=10000 10 3 benchmark/results/my-run"
```

Аргументы: запросы, клиенты, повторения, папка результатов.
Можно дополнительно указать REST URL, gRPC host и gRPC port.
Каждый повтор содержит указанное количество запросов **на каждый протокол**.
Например, 10000 / 10 / 3 = 60000 измеренных запросов суммарно.

Поддерживаются 1000, 10000, 50000 запросов и 1, 10, 50 клиентов.
По умолчанию выбран сценарий 10000 / 10, три повтора.
Для другого сценария меняйте первые два числа и используйте новую папку.
Не запускайте benchmark одновременно с тестами.

Выход: raw.csv (каждый запрос), summary.csv (сводка), environment.txt.
Папка должна быть новой: повторный запуск в ту же папку перезаписывает результаты.

Измеряется GET одного товара. На каждый протокол и повтор — 1000 прогревочных
запросов, которые не попадают в CSV. Клиенты работают параллельно, соединения
переиспользуются. REST использует HTTP/1.1, gRPC — HTTP/2. Повторы отключены.
Протоколы чередуют порядок. Тайм-аут — 2 секунды.

p50/p95/p99 рассчитаны методом nearest rank только для успешных запросов.
Ошибки сохранены в raw.csv и отдельно посчитаны в summary.csv.
RPS = успешные запросы / полное время измерения.
Размер ответа — JSON UTF-8 или Protobuf, без заголовков, TCP и gRPC framing.
Это **не полный сетевой трафик**.

Это closed-loop тест: каждый клиент отправляет следующий запрос после ответа.
Он не моделирует независимый входящий поток и не доказывает предельную пропускную
способность сервиса. Один горячий товар, локальная сеть и тёплая БД облегчают нагрузку.
